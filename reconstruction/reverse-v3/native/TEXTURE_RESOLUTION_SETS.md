# Texture resolution sets (SD/HD copies of the same asset)

Generated by `tools/audit_texture_sets.py` from the extracted original assets.
The original ships SD and HD copies side by side (`GameResources/<name>` and
`GameResources/HDTex/<name>`), and the rebuild has to sample the right one at the
right scale - so this table is per name and per axis, not a global constant.

## Counts (current run)

| class | count |
|---|---:|
| basenames shipping more than one copy | 127 |
| SD/HD resolution pairs | 122 |
| identical duplicates (same bytes at two paths) | 2 |
| same size, different content | 2 |
| several sizes, no HDTex counterpart | 1 |
| non-uniform ratio (width and height scale differently) | **1** |
| non-integral ratio | 0 |

Ratio histogram over the 122 pairs: **4x: 97, 8x: 23, 2x: 1, 32x: 1**.

## Why a global scale factor is wrong

- `Sun.png` goes 16x16 -> 512x512, a **32x** step, while `sharkSideFin.png` goes
  16x16 -> 32x32 (**2x**) and the bulk is 4x. Scaling by the usual 4 (or by the
  8 used for the font atlas) is wrong for 25 of the 122 pairs.
- `yakNeck.png` is 16x16 -> 128x64: **8x horizontally, 4x vertically**. A
  `scale = hd.width / sd.width` shortcut applied to both axes would stretch it to
  double height. This is the only non-uniform pair, which is exactly why it is
  easy to miss.

## The directory is not the signal

- `hat_santa.png` sits under `HDTex/` while its bytes are identical to the SD
  copy: `HDTex/` membership does not imply a different resolution.
- `bannedPainting.png` (16x16) and `tulipFlower.png` (64x64) differ in content
  between SD and HD but are the same size in both, so "HD" is not a size test
  either.
- `mainMenuBackground.png` ships at two sizes with no `HDTex/` counterpart at all.

The safe rule for a loader is therefore: look up the measured `(width, height)`
per name (this table), never infer the variant from the path or from a shared
scale constant.

## Boundaries

- Dimensions come from the PNG IHDR; content is compared by sha256 only for the
  "identical duplicate" class.
- This is a catalogue of what ships, not a statement about which copy the original
  loads on a given device (the three files under `iOS` shell paths are unrelated).
- The 2 identical duplicates and the 2 same-size pairs are recorded, not
  explained; no attempt is made to say which copy the original prefers.
