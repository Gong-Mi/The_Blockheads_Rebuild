# Draw-value domains: are these numbers the same kind of thing?

Four independently extracted sets of numbers describe draws in this repository. This
cross-check answers a question the earlier artefacts left open - whether the shared
body's values, the direct tile cases' images and the item sprite images are the same
domain or different ones. Generated by `tools/crosscheck_draw_value_domains.py`.

## Sets (current run)

| set | count | min | max |
|---|---:|---:|---:|
| direct tile cases (`draw_image`) | 44 | 192 | 606 |
| tile map inline (`image_dataA0`) | 33 | 32 | 746 |
| item sprite images (`image`) | 47 | 32 | 746 |
| shared body draw values (49 slots) | 49 | 32 | 746 |
| shared body constants (compared against `[fp,-0x540]`) | 6 | 224 | 512 |

## Overlaps

| pair | shared | only in A | only in B |
|---|---:|---:|---:|
| shared body vs item sprite images | **37** | 12 | 10 |
| shared body vs direct tile cases | 0 | 49 | 44 |
| direct tile cases vs item sprites | 0 | 44 | 47 |
| **constants vs direct tile cases** | **6 / 6** | 0 | 38 |

## What that establishes

- The shared body's 49 draw values are the **same kind of number as the item sprite
  images** (37 of 49 appear in that set): they are image ids, not a private enum.
  This is what settles R23's open question with data rather than reading.
- The direct tile cases' images are a **different sub-domain**: 0 overlap with both
  the sprite images and the shared body's draws, spanning 192-606.
- All **six** constants the shared body compares against `[fp,-0x540]` are members of
  the direct-case image set. So `[fp,-0x540]` carries an image chosen by the direct
  cases, and the shared body is special-casing six particular images.

## Boundaries

- Set membership only: overlapping ranges show the values are interchangeable kinds,
  not which texture page each id resolves to.
- The four sets come from three different extractions; a shared numeric domain does
  not by itself prove the renderer treats them identically.
- No draw, frame capture or device run.
