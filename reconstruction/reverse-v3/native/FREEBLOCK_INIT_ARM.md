## Execution corrected three static readings

1. **subItems is an ARRAY OF ARRAYS.** The original creates a FRESH
   NSMutableArray (alloc+init via the classref, stored into `self->subItems`
   at 0x627000) BEFORE reading the save-dict `subItems` key. The outer
   NSFastEnumeration walks per-element slot arrays; for each element it
   creates a temp `[NSMutableArray array]`, appends it to
   `self->subItems`, and then enumerates the element's payloads into
   InventoryItem children (`alloc` + `initWithSaveData:` + `autorelease`
   + `itemType`), skipping `itemType == 11` children, into the temp.
   The b3m-3 static read ("InventoryItem children into FreeBlock.subItems")
   collapsed this two-level structure into one level.
2. **The 64-bit priority resolution asks the DYNAMIC WORLD.**
   `priorityBlockheadUinqueID` (the original's own typo) is read as an
   intValue, sign-extended to 64 bits (asr #31), and — when non-zero —
   resolved via `[dynamicWorld blockheadWithIDIncludingNet:]` + `retain`
   into `priorityBlockhead@136`. The static read attributed the receiver
   to `world`; the ivar chain in the listing (offset storage 0x0105C3A8 =
   DynamicObject.dynamicWorld) proves the executed receiver.
3. **The hovers re-anchor targets CREATION TIME, not floatPos.** After the
   900s age gate (`worldTime - creationTime > 900.0`, ARM `ble` edge), the
   inline itemType gates (0x1b/0x8e/0x8c/0x8f/0x8d then 0xcd/0xd0/0xce/0xcc),
   the `0x627C40` blacklist helper and the `0x5B2AD4` liquid predicate, the
   original computes `elapsed = (float)(worldTime - creationTime - 900.0)`,
   clears `hovers`, and stores
   `creationTime = worldTime - (double)elapsed` (all three worldTime calls
   re-read the world). floatPos is untouched by the re-anchor — only the
   ground-fall loop's `floatPos.y -= 1.0f` touches it. The earlier "floatPos
   re-anchor" reading misattributed the store target.

## Ground-fall loop (executed)

`elapsed < 900.0f` (ARM `bpl` skips) opens a max-16-step loop: each step
queries `[world tileAtX:pos.x y:pos.y-1]` (0x00A12F24 hook; the tile-kind
helper 0x00A12300 and position builder 0x004B49FC and floatPos identity
helper 0x004BDAAC run NATIVELY); a solid tile (byte[0] == 2) does
`floatPos.y -= 1.0f` + `[self updatePosition:{x, y-1}]` and CONTINUES (pos
re-read next step); absent or soft tiles break. The 16-cap case proves the
loop limit (16 and 20 solid fixtures both stop at 16 queries / 16 falls,
pos.y -5 → -21). Then `updateNeedsToBeSent = 1` (strb at 0x627AD0) and
`[dynamicWorld dynamicWorldChangedAtPos:objectType:]` fire.

## Harness facts

* GOT 0x0105FB70 = `memset` and 0x0105FD1C = `objc_enumerationMutation`
  behind veneers 0x1C2924/0x1C2E28 — identified via `.rel.plt` and patched
  to stubs (32-bit NSFastEnumerationState: state@0, itemsPtr@4,
  mutationsPtr@8 — the b4m chest precedent; a wrong itemsPtr offset reads
  element tokens from vaddr 0).
* The NSMutableArray classref slot (0x00E8A1AC) is relocation-resolved at
  load; in the harness it reads 0, so `alloc`/`array` receivers are 0. The
  InventoryItem classref (0x00E8A1B0) carries 0x00E91CA0 on disk.
* The super handler asserts the objc_super struct (receiver + OWN class
  0x00E907B0, superref slot 0x00E8BC78) and all FOUR forwarded arguments.
