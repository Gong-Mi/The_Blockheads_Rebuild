# Audio wiring map: every shipped sound -> the method that references it

Evidence grade: **A** for the mapping (pointer arithmetic over the pinned ELF, regenerated by
`tools/extract_audio_wiring_map.py`, with a five-entry self-check), **membership only** - this says
where a name is referenced, not when or how it plays.

Companion artifacts: `audio_wiring_map.json`, `audio_wiring_map.tsv`. Coverage source of record:
`audio_asset_coverage.json` (161 shipped / 152 named by the original / 16 referenced in the
replacement / 136 not referenced).

## Why this closed a gap that looked blocked

The audio line was recorded as "wiring unresolved, blocked on the send channel". That channel is
indeed nearly empty (`audio_call_site_literals.json` holds one function for `soundNamed:` with
`literals: []`), because most playback goes through a dispatch form the selector tools do not model.
The names do not need that channel:

```text
cstring "blockheadDie.wav"  ->  __cfstring struct (+8 points at the cstring)
                            ->  a pool word equal to (cfstring_va - PIC_BASE 0x105faf4)
                            ->  the ldr site that loads it
                            ->  the enclosing method (prologue scan + method table)
```

Sample, hand-checked before the sweep:

| sound | method |
|---|---|
| `blockheadDie.wav` | `Blockhead -[dieForGood]` |
| `camera.wav` | `World -[doCameraScreenshot]` |
| `babyUnicorn.wav` | `Donkey -[loadDerivedStuff]` |
| `bow.wav` | `Blockhead -[update:accurateDT:isSimulation:]` |
| `buzz1.wav` | `Workbench -[draw:projectionMatrix:modelViewMatrix:...]` |

## Result

| | |
|---|---|
| names considered | 161 |
| **mapped to a referencing method** | **136** |
| no `__cfstring` struct (referenced some other way) | 2 |
| cfstring but no located site | 0 |
| cstring absent verbatim (composed at run time) | 23 |

Of the mapped rows, **120 are still unreferenced by the replacement** - the mechanical
wiring backlog, each row carrying the method and the pool-word site so a wiring commit can cite an
address. Sounds per method (top): `World -[incrementalLoad]...` (26), `Blockhead -[update:accurateDT:isSimulati...` (22), `Workbench -[draw:projectionMatrix:modelV...` (13).


## The backlog shape

120 of the mapped names are still unreferenced by the replacement, spread over 110 distinct
methods. The concentration is informative rather than uniform: `World -[incrementalLoad]`
alone names 26 of them (a load-time list, the natural first wiring target), 
`Blockhead -[update:accurateDT:isSimulation:]` 22, `Workbench -[draw:...]` 13,
`Donkey -[loadDerivedStuff]` 6, `World -[preRenderUpdate:...]` 6.

## What this does and does not establish

- Does: which method in the original references each shipped name, with the site address.
- Does not: playback semantics. A reference says the code names the sound, not that this is the only
  moment it plays. The `no_cfstring` (2) and `cstring_absent` (23)
  rows are recorded rather than guessed: `axe.wav` is one of the two no-cfstring names, so it is
  composed some other way and stays open.
