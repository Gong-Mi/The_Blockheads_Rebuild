# Font asset tables (BMFont metrics from the original .fnt files)

Generated by `tools/parse_original_fonts.py`. Text is an asset line item: the
replacement cannot lay out a label without the metrics, so the shipped
descriptors are parsed into a glyph table and their declared atlas size is
cross-checked against the actual PNG.

## Findings recorded rather than normalised away

- **`04b03_16` atlas is 8x its declared canvas.** The descriptor declares
  256x128; the shipped PNG is 2048x1024. The glyph extents stay inside the
  declared canvas (max x+w = 256, max y+h = 82), so the metrics are internally
  consistent and the sampler has to scale by 2048/256 = 8. Reading the declared
  size as the texture size would sample the top-left eighth of the atlas.
- **The two 64px fonts share one atlas** (`Blockheads_64.png`): the "black"
  variant is not a separate texture, so the difference has to come from a tint or
  a uniform rather than a different page.
- **ASCII 126 (`~`) is absent in both 64px fonts** (2 missing = 1 per font); the
  16px faces carry all 95 codepoints. Anything that renders `~` with the 64px
  face needs a fallback.
- No kerning pairs ship in any of the five files.

## Boundaries

- Metrics only: this says nothing about how the original rasterises, tints or
  caches text, and the 8x reading above is an inference from the size ratio plus
  the in-canvas extents, not a traced sampler.
- The glyph table is the shipped data; an atlas can be re-packed by a later build.
- The replacement currently references no `.fnt` at all, so every row here is
  unwired.
