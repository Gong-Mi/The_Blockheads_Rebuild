# The audio API the replacement has to answer

Wiring the 161 shipped audio files needs a sound system, and the client already defines
what that system looks like. Two sources are joined per class: the ObjC method map
(selectors, kind, IMP) and the binary's own `OBJC_IVAR_$` entries.
Generated by `tools/extract_audio_api.py`.

## The surface, by role

**`MJSoundManager`** - the owner. Loading and lookup: `soundNamed:`,
`multiSoundNamed:`, `multiSoundWithSounds:`, `externalMultiSoundWithKey:`. Mixing and
space: `setSoundVolume:`, `setMusicVolume:`, `soundVolume`, `musicVolume`,
`setListenerPosition:zoom:`, `listenerPos`, `update:`. Streaming: `playMP3IfSafe:`,
`playMP3IfSafe:withTimeOffset:`, `loadMP3IfSafe:withTimeOffset:`, `stopMP3Playback`,
`fadeInMP3Playback`, `fadeOutMP3PlaybackWithStop:`,
`fadeOutMP3PlaybackWithFinishNotificationObject:action:stopOnFadeOut:`, `isPlayingMP3`,
`currentMP3time`, `setLoopMP3s:`, `mainThreadSetMP3Volume:`. Lifecycle:
`initWithMasterVolume:`, `reinitialize`, `resignActive`, `becomeActive`,
`handleInterruption:`, `interruptionBegan`, `interuptionEnded`,
`attemptToReinitializeAudio`, `safeToPlayMP3s`, `setRequiresRecord:`, `instance`.

**`MJSound`** - one sound. `initWithFile:`, `initWithSound:`, `openFile:`,
`openWAVFile:`, `loadWavFile:format:size:frequency:data:`, `fileName`, `sound`, `buffer`;
playback `play`, `playAfterDelay:`, `playAtPosition:`, `stop`, `pause`, `setPaused:`,
`fadeOut:`, `setVolume:`, `setLegacyVolume:`, `getLegacyVolume`, `setPitch:`,
`setLooping:`, `setPosition:`, `setXOffset:`, `hasFinishedPlaying`, `isPlaying`,
`setInUse:`, `isInUse`, `setMasterVolumeMultiplier:`, `update:`; variation
`setMultiSoundPlayBackFrequency:`, `multiSoundPlayBackFrequency`,
`randomNumberWithinMultiPlaybackFrequency`, `hasMultiSoundPlayBackFrequency`,
`setHasMultiSoundPlayBackFrequency:`.

**`MJMultiSound`** - a group played as one event, including
`backgroundThreadPlayWithDelay:` and `incrementalPitchOffset`.

**`SoundOptionsUI`** - the options screen (13 methods), i.e. the volume/silent controls.

Its ivars tell the shape of the system without reading a body: `loadedSounds`,
`loadedMultiSounds`, `loadedSoundsArray`, `soundVolume`, `musicVolume`, `mp3Player`,
`loopMP3s`, `fadingOut`/`fadingIn`, `fadeOutCompleteAction`, `dontPlayAnySounds`,
`alContext`/`alSuspended`/`device` (OpenAL - matching `libOpenAL.so` in the APK),
`requiresRecord`, `externalMultiSounds`, `pingForLoopDelayTimer`.

## What this is and is not

- It **is** the call surface: the selectors a sound implementation must answer, taken
  from the binary rather than invented, so the replacement can be written against it.
- It **is not** the wiring. Which game action asks for `dig.wav` is a call-site question:
  the names live in `__cfstring` entries (213 of them point at the 139 audio name
  strings), and no code loads those entries by a pc-relative literal, `movw/movt` pair or
  `add pc` - they are reached indirectly, and that indirection is unsolved. The load path
  itself is visible here: `MJSoundManager soundNamed:` / `MJSound initWithFile:`.

## Boundaries

- Method lists come from the in-repo ObjC map; a selector that exists but is dead is
  indistinguishable from a live one here.
- Ivars are listed by name only - offsets and types are in `CLASS_TABLE.md`.
- No audio was played and no device run happened.
