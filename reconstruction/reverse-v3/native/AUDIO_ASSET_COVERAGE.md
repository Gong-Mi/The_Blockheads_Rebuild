# Audio asset coverage (shipped vs original-referenced vs replacement-referenced)

Generated by `tools/audit_audio_assets.py` from the extracted original assets,
the pinned `libApplication.so` and the replacement sources. Membership only - it
makes no claim about playback, volume, mixing or when a sound fires.

## Counts (current run)

| class | count |
|---|---:|
| audio files shipped in the original assets | 161 |
| names referenced verbatim by the original ELF | 138 |
| names present only as a **stem** in the ELF (composed at runtime) | 14 |
| names the replacement sources mention | 16 |
| shipped but referenced by neither (candidate dead weight) | 9 |
| original-referenced (verbatim or stem) but not named by the replacement | **136** |
| names the ELF references that ship no file | 1 |

## The stem-only class

Fourteen files (all `bird1..bird14.wav`) have no verbatim string in the ELF
because the original composes the name at runtime from the stem `bird` plus an
index. They are recorded as `original_stem_only` rather than filed under "no one
references this" - the stem hit is the evidence; which index plays when is not
claimed here.

## The one missing file

`_KelpPlant.wav` appears as a string in the original binary while no such file
ships in the assets. Either the original guards it before use or the asset was
dropped from this build; the table records the observation and leaves the cause
open.

## The integration gap

`original_not_in_replacement = 136` is the concrete list a playback
implementation has to work through: the replacement currently names 16 audio
files while the original references 138. Each row of
`audio_asset_coverage.tsv` carries the file's sha256, so wiring work can be
verified against the exact shipped bytes.

## Boundaries

- "Referenced" is a byte-string membership test on the ELF, not a call-site
  analysis: a name that only appears in dead data would still count.
- The stem heuristic strips trailing digits; it is deliberately conservative and
  its hits are reported as their own class.
- The 9 "shipped but unreferenced" entries are candidates, not proof of dead
  weight (they may be referenced through a name built at runtime that the stem
  heuristic cannot see).
- No device run, no audible check.
