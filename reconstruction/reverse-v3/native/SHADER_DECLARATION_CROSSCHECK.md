# Shader mapping cells vs the shipped shader sources

Generated by `tools/crosscheck_shader_declarations.py`, which reads
`shader_mapping.tsv` (34 rows, per UI class/method) and the actual `.vsh`/`.fsh`
declarations, then classifies every token in the mapping's attribute and uniform
cells.

## Counts (current run)

| class | count |
|---|---:|
| mapping rows | 34 |
| distinct shaders referenced | 8 |
| referenced shaders whose source file is missing | 0 |
| tokens in the attribute/uniform cells | 147 |
| - declared `attribute` in that shader | 41 |
| - declared `uniform` in that shader | 43 |
| - optional (`?`-marked) and declared | 0 |
| - **not declared anywhere in the shader** (binding markers) | **63** |
| rows containing at least one binding marker | 27 |
| declared attributes no mapping row ever mentions | 97 |

## The finding: those cells are not a declaration list

43% of the tokens in the attribute/uniform cells name something the shader does
not declare. Examples straight from the table:

| row | cell | undeclared tokens |
|---|---|---|
| `CustomGameRulesUI ... StandardObject` | attributes `?color,ColoredNoTexture` | `ColoredNoTexture`, `color` |
| `... ColoredNoTexture` | attributes `position,?StandardObject,texture,texCoord` | `StandardObject`, `color`, `texCoord`, `texture` |

`StandardObject.vsh` declares `position` and `texCoord`; `texture` and
`ColoredNoTexture` appear nowhere in any of the 92 shipped programs. They are
binding markers - the name of a texture source, a variant selector, a constant -
not attributes. Treating the cell as "the attributes this shader has" would invent
inputs that the shader never reads.

The tool therefore classifies every token instead of diffing two sets, so a
mismatch claim cannot be produced by a marker.

## The 97 never-claimed attributes

The mapping table covers 34 UI class/method rows over 8 shaders, while 46 shaders
ship. Attributes of programs the table never mentions (e.g. `other`/`paintColor`
in `Block.vsh`, `normal` in the `Blockhead*` programs, `texCoordB` in the dodo egg
programs) are therefore not "missing from the mapping" in any meaningful sense -
they are simply outside its scope. The per-shader list is in the JSON
(`never_claimed_attributes`).

## Boundaries

- Declarations are parsed from the shipped GLSL text, comments excluded; a
  declaration behind a preprocessor branch would be counted only if it appears
  literally.
- "Binding marker" is a negative classification (not declared in the shader). It
  does not claim what the marker means.
- No GL/Vulkan program was compiled and no device run happened.
