# Tile sprite domain (all 77 TileTypes)

Generated by `tools/resolve_tile_sprite_domain.py`, which joins three
independently extracted artifacts and records where each cell came from instead
of flattening them into one column:

| source | what it contributes |
|---|---|
| `original_tile_item_map.tsv` | the `isForeground == 0` switch of `itemTypeFromTileIsForegorund()`: every direct tile type, its mapped ItemType, and for 43 rows that item's sprite cell inline |
| `original_item_sprite_map.tsv` | the item sprite domain (426 ItemTypes, R2): a cell for any ItemType |
| `original_tile_conditional.tsv` | the conditional tile types, resolved through `contentsType()` compare chains (87 rows / 4 cases) |

## The cross-check

The tile map and the item sprite domain are separate extractions of separate
functions (`itemTypeFromTileIsForegorund` @`0x00a18044` and
`texCoordsForItemType` @`0x004d6040`). For the 43 tiles whose row carries a cell,
that cell must equal the item domain's cell for the same ItemType - and it does,
in all 43 cases (`tile 4 -> ItemType 1060 -> col 14, row 3`; `tile 7 -> 1051 ->
1, 2`; ...). Two extractions agreeing is evidence; the tool counts mismatches and
would report them as findings rather than dropping them.

## The 25 derived cells

These tiles map to an ItemType but their switch case does not carry the item's
sprite fields. Their cell is taken from the item domain for that ItemType, which
covers the whole 426-type range (ItemType 0 included - 24 of the 25 are ItemType
0, which the domain resolves to cell (0, 0)).

## The 9 conditional tiles

`1 2 3 5 6 12 13 27 28 ...` have no fixed cell: the case inspects Tile contents
before choosing, so the answer is a compare chain rather than a constant. They
are recorded as `contents-conditional` with their case target and the number of
resolved steps in the conditional table; they are deliberately **not** given a
guessed cell.

## Boundaries

- A cell is a position in `Items.png`; this says nothing about how the renderer
  composes tile overlays or when it uses the item sprite for terrain.
- The 25 derived cells are an indirection through ItemType, not an observed draw:
  they are marked with their own provenance for that reason.
- No device run, no frame capture.
